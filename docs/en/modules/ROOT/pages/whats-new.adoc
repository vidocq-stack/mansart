= What's new
:description: Everything that changed in this component since the {release-version} release.

[.lead]
New in the `{project-version}` development line — everything listed here landed **after the {release-version} release** and is not part of it. Every entry links to the section that documents it, and those sections carry the [.tag-new]#NEW# badge. Each brick of the suite keeps its own page of this kind; xref:home::whats-new.adoc[the ecosystem index] gathers them. When the next release train ships, this page is frozen with it and restarts empty on the dev line.

== Build

* xref:usage.adoc#private-repositories[A private repository is a compile error] [.tag-new]#NEW# — a `@Repository` interface that is `private`, or nested in a `private` type, fails the build with the fix in the message, instead of a compiler note and a repository served at run time, which a named module cannot do; `-Amansart.privateRepositories=warn` keeps the previous behaviour. A repository declared inside a method is refused at run time with a message (Vidocq/mansart#85).
* xref:internals.adoc#codegen-apt[`Outer_BookRepositoryImpl`] [.tag-new]#NEW# — the implementation of a nested repository is named with `_` where its binary name has `$`, so no top-level generated class carries a `$`; `META-INF/mansart-repositories.list` names the class, so an index written by an earlier processor stays valid (Vidocq/mansart#85).
* xref:usage.adoc#dependency-repositories[A repository of a jar the build did not enrich] [.tag-new]#NEW# — the deployment error names the repository, the bean that injects it, the jar and the fix (`vidocq:generate`, `scanDependencies`, `scanExcludes`, `mansart-data-processor`), instead of a bare unsatisfied dependency (Vidocq/mansart#85).
* xref:usage.adoc#find[A nameless `@Find` parameter is an error] [.tag-new]#NEW# — a repository compiled without `-parameters` and without `@By` fails the build, or the creation of the repository on the run-time path, naming the method; the former binding to the entity's only attribute of the parameter's type was a guess the specification (§4.3) does not allow (Vidocq/mansart#85).
