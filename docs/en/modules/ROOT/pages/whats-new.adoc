= What's new
:description: Everything that changed in this component since the {release-version} release.

[.lead]
New in the `{project-version}` development line — everything listed here landed **after the {release-version} release** and is not part of it. Every entry links to the section that documents it, and those sections carry the [.tag-new]#NEW# badge. Each brick of the suite keeps its own page of this kind; xref:home::whats-new.adoc[the ecosystem index] gathers them. When the next release train ships, this page is frozen with it and restarts empty on the dev line.

== Pool

* xref:modules/mansart-pool.adoc#session-reset[Session attributes put back on release] [.tag-new]#NEW# — the transaction isolation, read-only flag, catalog, schema, holdability, network timeout and type map a borrower changed no longer reach the next borrower of the same connection; only the attributes changed are read and put back (MANSART-047).
* xref:modules/mansart-pool.adoc#pending-work[No second rollback on release] [.tag-new]#NEW# — a connection handed back out of auto-commit is rolled back only when a statement ran since the last `commit()` or `rollback()`; a committed transaction no longer pays a rollback, which on H2 emptied the statement cache. Statements are wrapped to track this, and `Statement.getConnection()` now returns the pooled connection instead of the driver's (Vidocq/noether#45).
* xref:modules/mansart-pool.adoc#closed-handle[A closed connection is dead] [.tag-new]#NEW# — after `close()` the handle and its statements throw `SQLException` (SQLSTATE `08003`) instead of reaching the physical connection, which another borrower may hold: a `rollback()` on a closed handle rolled back that borrower's transaction. A driver's unchecked exception during the reset no longer costs the pool one of its `maxSize` places (MANSART-056, MANSART-057).
* xref:modules/mansart-pool.adoc#idle-maintenance[Idle connections are validated, `minIdle` is held] [.tag-new]#NEW# — `ValidationMode.PERIODIC`, the default, checked nothing, and `validationQuery` was never run: a connection the database dropped was the next borrower's error. The housekeeper now checks the idle connections and closes the dead ones, the `validationQuery` is what checks when it is set, and the pool keeps `minIdle` connections through the idle timeout and opens new ones to reach it again; `minIdle` was honoured at start-up only (MANSART-058, MANSART-059).

== Transactions

* xref:modules/mansart-transactions.adoc#completion[A rollback-only mark set in `beforeCompletion` rolls back] [.tag-new]#NEW# — the transaction was committed all the same; `commit()` now rolls back and throws `RollbackException` (MANSART-051).
* xref:modules/mansart-transactions.adoc#completion[A synchronization may register another from `beforeCompletion`] [.tag-new]#NEW# — it failed with `ConcurrentModificationException` and the transaction rolled back (MANSART-052).
* xref:modules/mansart-transactions.adoc#completion[The caller of nested `@Transactional` methods sees its own exception] [.tag-new]#NEW# — a second `setRollbackOnly()` threw `IllegalStateException`, which replaced the business exception as soon as it crossed two joined calls (MANSART-053).
* xref:modules/mansart-transactions.adoc#completion[An `Error` rolls the transaction back] [.tag-new]#NEW# — it left the transaction bound to the thread, its connections never given back (MANSART-054).
* xref:modules/mansart-transactions.adoc#completion[A two-phase commit reaches every resource] [.tag-new]#NEW# — the first failing resource stopped the loop and left the others prepared, their locks held, until a restart (MANSART-055).

== Build

* xref:usage.adoc#private-repositories[A private repository is a compile error] [.tag-new]#NEW# — a `@Repository` interface that is `private`, or nested in a `private` type, fails the build with the fix in the message, instead of a compiler note and a repository served at run time, which a named module cannot do; `-Amansart.privateRepositories=warn` keeps the previous behaviour. A repository declared inside a method is refused at run time with a message (Vidocq/mansart#85).
* xref:internals.adoc#codegen-apt[`Outer_BookRepositoryImpl`] [.tag-new]#NEW# — the implementation of a nested repository is named with `_` where its binary name has `$`, so no top-level generated class carries a `$`; `META-INF/mansart-repositories.list` names the class, so an index written by an earlier processor stays valid (Vidocq/mansart#85).
* xref:usage.adoc#dependency-repositories[A repository of a jar the build did not enrich] [.tag-new]#NEW# — the deployment error names the repository, the bean that injects it, the jar and the fix (`vidocq:generate`, `scanDependencies`, `scanExcludes`, `mansart-data-processor`), instead of a bare unsatisfied dependency (Vidocq/mansart#85).
* xref:usage.adoc#find[A nameless `@Find` parameter is an error] [.tag-new]#NEW# — a repository compiled without `-parameters` and without `@By` fails the build, or the creation of the repository on the run-time path, naming the method; the former binding to the entity's only attribute of the parameter's type was a guess the specification (§4.3) does not allow (Vidocq/mansart#85).
* xref:usage.adoc#dependency-repositories[A library's `Book_` is left as it is, `@Repository(provider)` is honoured] [.tag-new]#NEW# — `vidocq:generate` no longer fails on a library built with Hibernate Processor (`Mansart generated acme/lib/Book_.class, which the jar already has`): the JPA metamodel the jar ships is kept and only `_Book` is written; a repository declared for another provider is left to it, at build time and at run time (Vidocq/mansart#85).
* xref:reference.adoc#plural-attributes[An entity with a collection compiles] [.tag-new]#NEW# — an `@ElementCollection`, `@OneToMany` or `@ManyToMany` field, or one typed `List`, `Set` or `Map`, is no longer taken for a column: it is left out of `_Book`, which did not compile (`<identifier> expected` on `java.util.List<java.lang.String>.class`), and out of the model the run-time path builds, which selected a column the table does not have. Mansart repositories read and write the entity's columns and leave its collections to the persistence provider (MANSART-049).
* xref:concepts.adoc#static-metamodel[The JPA metamodel `Book_` is the persistence provider's] [.tag-new]#NEW# — `mansart-data-processor` writes the Jakarta Data metamodel `_Book` only. The `Book_` it wrote declared every attribute a `SingularAttribute`, a `List<Tag>` included, and kept the provider's processor from writing its own: Noether could not fill `Book_.tags`, and a Criteria query on the collection failed. An application that refers to `Book_` puts its provider's processor on the annotation processor path (xref:migration.adoc#upgrading-from-0-3-0[Upgrading from 0.3.0], Vidocq/noether#45).
