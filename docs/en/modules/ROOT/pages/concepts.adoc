== Jakarta Data 1.0 repositories

Three standard variants:

* `BasicRepository<T, K>` — minimal CRUD (`save`, `delete`, `findById`).
* `CrudRepository<T, K>` — extends `BasicRepository` with batch and named queries.
* `DataRepository<T, K>` — "free-form" repository to compose.

Plus **query methods**:

* derived from the name (`findByAuthor`, `countByYearGreaterThan`)
* explicit via `@Query("SELECT b FROM Book b WHERE b.author = ?1")`

== JDBC dialects

`mansart-jakarta-data` speaks SQL through a **dialect** SPI:

* `MansartDialect` — single interface: JDQL → SQL translation, JDBC types, pagination syntax, upsert syntax.
* `H2Dialect` — reference for in-memory tests.
* `PostgresDialect` — production target.

== JDBC pool

`mansart-pool` exposes a minimal pool `DataSource`: virtual threads, no JNDI, configurable via MicroProfile Config.

== Transactions

`mansart-transactions` exposes:

* Jakarta Transactions `UserTransaction`;
* `@Transactional` (CDI interceptor provided by the module);
* `REQUIRED`, `REQUIRES_NEW`, `MANDATORY`, `SUPPORTS` propagation.

Vidocq integration goes through the `vidocq-mps-mansart-transactions-extension` extension (already shipped — see the `vidocq` repo).

== Design choices

* **No implicit auto-flush** — the user calls `flush()` explicitly or ends the transaction.
* **No `EntityManager` proxy** — the API is consumed directly.
* **No runtime entity scan** — the APT registers entities at compile time.
