== Jakarta Persistence 3.2 — inheritance milestone

Runner: `mansart-persistence/mansart-jpa-tck`, out of the reactor, using the official unmodified 3.2.1 suite
and PostgreSQL 17 DDL.
The P6 full run passes 1005 tests, compared with 909 in the rebuilt pre-P6 checkout:
96 newly passing tests, no test-by-test regression.
The older documented score of 897 predates that checkout's partial native-result changes.

The inheritance, discriminator and inheritance-callback gates report 19 / 21 passed.
Only two mapped-superclass descriptor tests remain, waiting for XML mappings (P10); they are not excluded.
Required `SINGLE_TABLE` and `JOINED`, polymorphic loading and JPQL `TYPE` are delivered.
Optional `TABLE_PER_CLASS` remains explicitly refused; decision D5 stays open.
Criteria/metamodel/graphs, schema generation, XML, unfinished query/native/stored-procedure cases and caching/validation remain ahead.

[source,bash]
----
cd mansart/main/mansart-persistence/mansart-jpa-tck
./run-official-tck-persistence-3.2.sh
----

The script exits zero once it produced a report even if tests failed; inspect
`target/tck-report-persistence.txt` and the failsafe XML counters.
The two known native constructor-result failures remain unchanged.

== Jakarta Data 1.0 — detail

Runner: `mansart-jakarta-data/mansart-data-tck`, **out of reactor** (standalone POM Model 4.0.0, no `<parent>`). Reason: ShrinkWrap Maven Resolver 3.3 cannot parse Maven Model 4.1.0 (see workspace `CLAUDE.md`).

Harness architecture:

* Arquillian + ShrinkWrap for the official TCK fixtures.
* Mansart adapter: `MansartRuntimeProducer` injects a `RepositoryRuntime` from a test H2 in-memory `DataSource`.
* `MansartTckArchiveAppender` + `VaubanArquillianExtension` enrich TCK archives with the Mansart implementations generated by APT.

Local reproduction:

[source,bash]
----
cd mansart/mansart-jakarta-data/mansart-data-tck
./run-official-tck-data-1.0.sh all
----

Major historical bug: `BUG-20260505-01` (TCK entities not metamodelled because compiled without the processor in the APT classpath). Resolved by the M7 runtime runner (`MansartRuntimeRepoCreator`). See link:{repo-mansart}/src/branch/main/mansart-jakarta-data/BUG.md[BUG.md].

== Jakarta Transactions 2.0 — detail

Runner: `mansart-transactions/`, see link:{repo-mansart}/src/branch/main/mansart-transactions/TCK.md[TCK.md].

The official TCK distributed by Eclipse is a historical **Sun tsharness** harness:

* `bin/build.xml` Apache Ant.
* `bin/ts.jte` ~80 properties (JAVA_HOME, SUT classpath, hostnames, ports).
* Tests under `src/com/sun/ts/tests/jta/ee/` compiled in place by `ant build` then executed via `ant runclient`.

No Surefire-scannable jar exists — `dependenciesToScan` against `jtatck.jar` only finds support classes, not tests.

Status:

* ✅ **M6** smoke wiring 5/5 (`./run-official-tck-transactions-2.0.sh smoke`).
* ✅ **M6b** profile `full-tck`: `ant build.all.tests` `BUILD SUCCESSFUL` on the ~7 JTA EE directories + signature tests.
* ⏳ **M6c** leaf-by-leaf driving + tsharness HTML report parsing.

Manual reproduction:

[source,bash]
----
cd mansart/mansart-transactions
./install-tck.sh                           # download + unpack
cd .tck-cache/transactions-tck/bin
$EDITOR ts.jte                             # JAVA_HOME, jta.classes, Mansart provider
ant build && ant runclient
xdg-open ../dist/index.html
----
