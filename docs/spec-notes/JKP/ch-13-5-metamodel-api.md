# 5. Metamodel API — Normative Requirements

## 5.1. Static Metamodel Classes

5.1.1 — The metamodel class X_ must be annotated with the StaticMetamodel annotation found in Section D.2.
5.1.1 — If the managed class X extends another class S (where S is the most derived managed class extended by X), then the metamodel class X_ must extend the metamodel class S_ created for S.
5.1.1 — The metamodel class must contain a field declaration: `public static volatile jakarta.persistence.metamodel.T<X> class_;` where T is EntityType, EmbeddableType, or MappedSuperclassType depending on whether X is an entity, embeddable, or mapped superclass.
5.1.1 — For every persistent attribute y declared by class X, the metamodel class must contain a field declaration: `public static final String Y = "y";` where Y is obtained by transforming each lowercase character in the attribute name y to uppercase, inserting an underscore if the character following the transformed character is uppercase, and replacing each character which is not a legal Java identifier character with an underscore.
5.1.1 — For every persistent non-collection-valued attribute y declared by class X, where the type of y is Y, the metamodel class must contain a declaration: `public static volatile SingularAttribute<X, Y> y;`
5.1.1 — For every persistent collection-valued attribute z declared by class X, where the element type of z is Z, the metamodel class must contain a declaration as follows: if the collection type of z is java.util.Collection, `public static volatile CollectionAttribute<X, Z> z;` if the collection type of z is java.util.Set, `public static volatile SetAttribute<X, Z> z;` if the collection type of z is java.util.List, `public static volatile ListAttribute<X, Z> z;` if the collection type of z is java.util.Map, `public static volatile MapAttribute<X, K, Z> z;` where K is the type of the key of the map in class X.
5.1.1 — For every named query, named entity graph, or SQL result set mapping with name "n" declared by annotations of the class X, the metamodel class must contain a declaration: `public static final String T_N = "n";` where the prefix T is the string QUERY, GRAPH, or MAPPING as appropriate depending on the annotation type, and the suffix N is obtained by transforming each lowercase character in the name n to uppercase, inserting an underscore if the character following the transformed character is uppercase, and replacing each character which is not a legal Java identifier character with an underscore.
5.1.1 — For every named query with name "n" and query result class R declared by annotations of the class X, the metamodel class must contain a declaration: `public static volatile TypedQueryReference<R> _n_;` where n is the name "n" with every character which is not a legal Java identifier character replaced with an underscore.
5.1.1 — For every named entity graph with name "n" declared by annotations of the class X, the metamodel class must contain a declaration: `public static volatile EntityGraph<X> _n;` where n is the name "n" with every character which is not a legal Java identifier character replaced with an underscore.
5.1.1 — Import statements must be included for the needed jakarta.persistence and jakarta.persistence.metamodel types as appropriate and all classes X, Y, Z, R, and K.
5.1.2 — Persistence providers must support the use of canonical metamodel classes.
