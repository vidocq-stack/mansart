## Reflection analysis (DEBT-04, DEBT-05)

### Current reflection usage in `mansart-jakarta-persistence`:

#### DEBT-04 BLOCKER — Criteria API uses `Proxy.newProxyInstance` (7 calls)
- `MansartCriteriaBuilder.java:170,271,292` — creates Root, generic criteria proxies, and CriteriaBuilder proxy
- `MansartCriteriaQuery.java:41` — creates CriteriaQuery proxy
- `MansartCriteriaUpdate.java:37` — creates CriteriaUpdate proxy
- `MansartCriteriaDelete.java:37` — creates CriteriaDelete proxy
- `MansartMetamodel.java:48,72` — creates Metamodel and ManagedType proxies

**Impact**: These are runtime proxies that dynamically dispatch all method calls. They return safe defaults (null, empty collections, 0, false) for unimplemented methods. This violates the charter: "APT-generated sources only, no runtime reflection."

**Remediation effort**: Large. Would require implementing ~20 interfaces from `jakarta.persistence.criteria.*`:
- `CriteriaBuilder` (50+ methods)
- `Root<T>`, `From<T,X>`, `Path<T>`, `Selection<T>` (30+ methods)
- `CriteriaQuery<T>`, `CriteriaUpdate<T>`, `CriteriaDelete<T>` (20+ methods)
- `Predicate`, `Expression<T>`, `ParameterExpression<T>` (20+ methods)
- `Join<T,X>`, `Fetch<T,X>`, `Subquery<T>` (15+ methods)
- Plus metamodel interfaces

**Recommended approach**: APT-generated stub classes at compile time, same pattern as `EntityMetadataGenerator`. The APT processor already scans entity classes — it could also generate Criteria implementation classes.

#### DEBT-05 — `MansartEntityManager` uses `java.lang.reflect.Field` (61 occurrences)
- `MansartEntityManager.java:660,702,1360,1396,1424,1432,1440,1449,1463,1472,1481,1491` — uses `Field` for schema generation and annotation detection
- **BUT**: Entity state read/write now uses APT-generated `MethodHandle` accessors via `AttributeAccessor` interface

**Current status**: The `Field` usage is limited to schema generation and annotation introspection (compile-time metadata, not entity state access). The critical path (persist/find/merge/remove) uses `EntityMetadata.readAttribute()` / `writeAttribute()` which use `MethodHandle`.

**Remediation**: Replace `Field` in schema generation with APT-generated column metadata. The APT processor already extracts column names, types, and constraints — this info could be stored in `EntityMetadata` and used by the schema manager.

### MethodHandles usage (compliant)
- `LifecycleCallbackManager` replaced by APT-generated `_EntityCallbacks` dispatchers
- `EntityMetadataGenerator` generates `MethodHandle`-based `SimpleAccessor` for each attribute
- `LOOKUP = MethodHandles.privateLookupIn(Entity.class, MethodHandles.lookup())` in each generated metadata class
