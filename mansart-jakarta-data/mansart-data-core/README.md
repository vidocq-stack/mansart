# mansart-data-core

Mansart Data runtime: standalone bootstrap, query plan execution, ResultSet ↔ entity mapping, repository call dispatch, **bytecode generation for `@Repository` implementations at runtime via Class-File API (JEP 484)**.

## Public entry points

| Class | Role |
| --- | --- |
| `MansartData` | Standalone bootstrap. `MansartData.builder().dataSource(ds).build()`. See root README. |
| `MansartData.Builder` | Fluent builder. `dataSource(DataSource)` required; `dialect(Dialect)` optional. |
| `RepositoryRuntime` | CRUD/JDQL operation executor. Held by `MansartData` or produced by CDI. |
| `MansartDataException` | Generic module exception. |
| `MansartCallback` | Dispatch holder used by generated classes. **Do not instantiate directly**. |

## Repository call flow

```
caller (virtual thread)
   ↓
HiddenClass <Repo>$$MansartImpl/0xNNNN.method(args)   ← generated bytecode
   ↓
MansartCallback.dispatch(methodIndex, Object[])
   ↓
Dispatcher (jdql / find / lifecycle / inherited / derived)
   ↓
RepositoryRuntime.<op>(EntityModel, args…)
   ↓
ConnectionScope (ScopedValue<Connection>)
   ↓
Dialect.{select,insert,update,delete,merge,paginate,bind,extract}
   ↓
JDBC PreparedStatement
```

## Runtime bytecode generation (M7-25)

`RuntimeRepositoryClassGenerator` produces, for each `@Repository` interface, a **hidden** class (`MethodHandles.Lookup#defineHiddenClass(bytes, true)`) that implements the interface. Each abstract method becomes a minimal stub:

1. pack arguments into an `Object[]` (with boxing of primitives),
2. call `callback.dispatch(methodIndex, args)`,
3. unbox / cast the return according to declared type.

No use of `java.lang.reflect.Proxy`, ASM, Byte Buddy or cglib. The generator only uses `java.lang.classfile`, `java.lang.invoke.MethodHandles` and `java.lang.constant.*`.

AOT compatible (GraalVM, Leyden CDS) — generated classes are hidden classes scoped to the interface package, they don't leak into the global ClassLoader.

## JDQL

`JdqlAst` + `JdqlExecutor` implement a subset of JDQL (Jakarta Data Query Language): `SELECT` / `FROM` / `WHERE` / `GROUP BY` / `HAVING` / `ORDER BY` / `UPDATE` / `DELETE`. See root README for the exhaustive list of operators.

## Java module

```java
module io.vidocq.mansart.data.core {
    requires io.vidocq.mansart.data.api;
    requires io.vidocq.mansart.data.dialect.spi;
    requires java.sql;
    requires jakarta.data;

    exports io.vidocq.mansart.data.core;
    uses io.vidocq.mansart.data.dialect.DialectFactory;
}
```

## Runtime dependencies

- `mansart-data-api`
- `mansart-data-dialect-spi`
- `jakarta.data-api`
- `java.sql` (JDK)

No direct JDBC driver dependency (the application brings them); no Jakarta CDI jar (CDI bootstrap lives in `mansart-data-cdi`).
