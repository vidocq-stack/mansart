# mansart-jakarta-data — Detailed Plan

Jakarta Data 1.0 (`jakarta.data:jakarta.data-api:1.0.x`) implementation with JDBC backend, pluggable dialects, and static repository generation.

## Target Jakarta Data 1.0 Scope

| Spec Concept | Mansart Implementation |
| --- | --- |
| `@Repository` | Detected by APT, generates `XxxRepositoryImpl` |
| `BasicRepository<T, K>` | Default methods implemented in `XxxRepositoryImpl` |
| `CrudRepository<T, K>` | Same |
| `DataRepository` (marker) | Detected |
| `@Find` | Generates a `SELECT … WHERE` from parameter names |
| `@Save`, `@Insert`, `@Update`, `@Delete` | Generates `MERGE`/`INSERT`/`UPDATE`/`DELETE` according to dialect |
| `@Query` (JDQL) | Parser JDQL → common AST → dialect SQL |
| `@OrderBy`, `Sort`, `Order` | Applied in the generated `ORDER BY` clause |
| `@By`, `@Param` | Parameter → column binding |
| `Limit`, `PageRequest`, `Page`, `CursoredPage` | Offset pagination (M3) then keyset (M3.5) |
| `Slice` | `PageRequest` variant without count |
| Static metamodel (`_Entity`) | Generated by APT |
| Lifecycle annotations (`@Insert`, `@Update`, `@Delete`, `@Save` typed) | One entity parameter → exact SQL |
| `EntityExists`, `OptimisticLockingFailureException`, `NonUniqueResultException` | Mapped from JDBC SQLState via the dialect |

**Out of scope v1**: NoSQL, non-standard `DataRepository` subtypes, complex projections (partial DTOs — coming in v1.1).

## Runtime Architecture

### Dialect Discovery

```java
ServiceLoader.load(DialectFactory.class)
    .stream()
    .map(ServiceLoader.Provider::get)
    .filter(f -> f.supports(dataSource))    // sniff JDBC URL or metadata
    .findFirst()
    .orElseThrow();
```

The sniffer queries `Connection.getMetaData().getDatabaseProductName()` only once at bootstrap. Global cache per `DataSource`.

### Repository Call Lifecycle

```
caller thread (virtual)
   │
   ▼
XxxRepositoryImpl.findByXxx(arg)        ← generated code, static
   │
   ▼
QueryPlan (immutable, computed at compile-time, instantiated 1×)
   │
   ▼
ConnectionScope.with(dataSource, conn -> {
   PreparedStatement ps = conn.prepareStatement(plan.sql())
   plan.bind(ps, args)
   ResultSet rs = ps.executeQuery()
   return plan.mapper().map(rs)          ← RowMapper also generated by APT
})
```

`ConnectionScope` uses a `ScopedValue<Connection>` to propagate the connection inside a transaction without `ThreadLocal`. If a `jakarta.transaction.UserTransaction` is active, it enlists; otherwise auto-commit.

### Static Metamodel

```java
// User source
@Entity
public class Book {
    @Id Long id;
    String title;
    @ManyToOne Author author;
    LocalDate publishedOn;
}

// Generated by mansart-data-processor in target/generated-sources/
@Generated("io.vidocq.mansart.data.processor")
public final class _Book {
    public static final EntityModel<Book> $MODEL = …;
    public static final Attribute<Book, Long>      id          = …;
    public static final Attribute<Book, String>    title       = …;
    public static final Attribute<Book, Author>    author      = …;
    public static final Attribute<Book, LocalDate> publishedOn = …;
}
```

The `Attribute`s are `record`s from the dialect SPI that expose `columnName()`, `javaType()`, `getter MethodHandle`, `setter MethodHandle`. **No runtime reflection** — MethodHandles are obtained at `<clinit>` once.

### Repository Generation

```java
// User source
@Repository
public interface BookRepository extends CrudRepository<Book, Long> {
    @Find
    List<Book> findByAuthorAndPublishedOnBetween(Author author, LocalDate from, LocalDate to);

    @Query("FROM Book WHERE title LIKE :pattern ORDER BY publishedOn DESC")
    Page<Book> search(String pattern, PageRequest pageRequest);
}

// Generated by APT
@Generated("io.vidocq.mansart.data.processor")
public final class BookRepositoryImpl implements BookRepository {
    private static final QueryPlan FIND_BY_AUTHOR_AND_PUBLISHED_ON_BETWEEN = QueryPlans.select(
        _Book.$MODEL,
        Where.and(Where.eq(_Book.author), Where.between(_Book.publishedOn)),
        OrderBy.NONE,
        Pagination.NONE);

    private static final QueryPlan SEARCH = QueryPlans.fromJdql(
        "FROM Book WHERE title LIKE :pattern ORDER BY publishedOn DESC",
        _Book.$MODEL);

    private final RepositoryRuntime runtime;

    BookRepositoryImpl(RepositoryRuntime runtime) { this.runtime = runtime; }

    @Override
    public List<Book> findByAuthorAndPublishedOnBetween(Author author, LocalDate from, LocalDate to) {
        return runtime.queryList(FIND_BY_AUTHOR_AND_PUBLISHED_ON_BETWEEN, author, from, to);
    }

    @Override
    public Page<Book> search(String pattern, PageRequest pageRequest) {
        return runtime.queryPage(SEARCH, pageRequest, pattern);
    }
    // … CrudRepository methods delegated to runtime
}
```

Instantiation is done by a CDI bootstrap (BCE Vauban) that does `Class.forName(itf.getName() + "Impl")` once, or directly by hand via `MansartData.repository(BookRepository.class, dataSource)`.

## SPI Dialect

```java
public interface Dialect {
    String name();
    boolean supports(DatabaseMetaData md);

    // SQL generation
    SqlFragment select(EntityModel<?> model, Where where, OrderBy orderBy, Pagination pagination);
    SqlFragment insert(EntityModel<?> model, boolean returningGeneratedKey);
    SqlFragment update(EntityModel<?> model, Where where);
    SqlFragment delete(EntityModel<?> model, Where where);
    SqlFragment merge(EntityModel<?> model);   // for @Save (upsert)

    // Pagination
    SqlFragment paginate(SqlFragment base, Pagination p);
    SqlFragment keyset(SqlFragment base, Cursor c);

    // Mapping Java ↔ SQL types
    int sqlType(Class<?> javaType);
    void bind(PreparedStatement ps, int idx, Object value, Class<?> javaType) throws SQLException;
    <T> T extract(ResultSet rs, int idx, Class<T> javaType) throws SQLException;

    // Error mapping
    DataException translate(SQLException e);
}

public interface DialectFactory {
    Dialect create();
    boolean supports(DatabaseMetaData md);
}
```

### Key H2 vs PostgreSQL Differences to Isolate in the Dialect

| Aspect | H2 | PostgreSQL |
| --- | --- | --- |
| Generated identifiers | `IDENTITY` + `Statement.RETURN_GENERATED_KEYS` | `RETURNING id` |
| Upsert (`@Save`) | `MERGE INTO … KEY(…) VALUES …` | `INSERT … ON CONFLICT (…) DO UPDATE SET …` |
| Offset pagination | `LIMIT n OFFSET m` | identical |
| Keyset pagination | tuple comparison `WHERE (col1, col2) > (?, ?)` | identical (row constructor syntax) |
| Booleans | native `BOOLEAN` | native `BOOLEAN` |
| `UUID` | native `UUID` | native `UUID` (driver converts) |
| `LocalDateTime` | `TIMESTAMP` | `TIMESTAMP WITHOUT TIME ZONE` |
| SQLState unique violation | `23505` | `23505` (common, can remain in shared layer) |
| SQLState optimistic lock | n/a (emulate via `version` column) | same |

### M7-28 — Compile-time RepositoryWriter: Parity with Runtime ✅ DONE (2026-05-05)

The compile-time `RepositoryWriter` only correctly supported `EQ`/`NOT_EQ`/`LT`/`LTE`/`GT`/`GTE`/`LIKE`/`BETWEEN`/`IN`/`IS_NULL`/`IS_NOT_NULL`. For comparators added at runtime (M7-8 and M7-27), there were latent bugs:

- `CONTAINS`/`STARTS_WITH`/`ENDS_WITH` → mapped to `Where.Like` but WITHOUT materialization of `%` around the arg → arg was passed raw to PreparedStatement → systematically empty results.
- `TRUE`/`FALSE` → mapped to `Where.Eq` but no `Boolean.TRUE`/`Boolean.FALSE` arg was added to `Object[]` → runtime bind count error.
- `EMPTY`/`NOT_EMPTY` → correct (no bind), but the mixed-In path didn't have the branch.
- `IgnoreCase` flag → completely ignored.
- `Not` (`negated`) flag → completely ignored.

- [x] `predicateExpr`: adds wrapping `IgnoreCase(...)` then `Not(...)` around the inner predicate.
- [x] New `renderArgsForPredicates(List<Predicate>)` that materializes:
  - `CONTAINS` → `"%" + p<i> + "%"`
  - `STARTS_WITH` → `p<i> + "%"`
  - `ENDS_WITH` → `"%" + p<i>`
  - `TRUE` → `Boolean.TRUE`, `FALSE` → `Boolean.FALSE`
  - `IS_NULL`/`IS_NOT_NULL`/`EMPTY`/`NOT_EMPTY` → no arg
  - `BETWEEN` → 2 refs, default → 1 ref
- [x] New helper `wrapIgnoreCaseAndNot(inner, p, pkg)` shared by predicateExpr and mixedInBody.
- [x] mixedInBody (In(Collection) case) propagates the same logic for all cases.
- [x] Entity fixture extended in `AuthorRepository` (compile-time): `findByNameContains`, `findByNameStartsWith`, `findByNameEndsWith`, `findByNameIgnoreCase`, `findByNameLikeIgnoreCase`, `findByNameNotIgnoreCase`, `countByNameIgnoreCase`, `deleteByNameIgnoreCase`, `findByNameContainsIgnoreCase`.

## Bootstrap (decision 1 — detailed)

### Mode A — Standalone

```java
MansartData md = MansartData.builder()
    .dataSource(ds)                        // required
    .dialect(MansartData.AUTO)             // or .dialect(new H2Dialect())
    .transactionManager(MansartData.AUTO)  // detects UserTransaction if JTA present, otherwise auto-commit
    .build();

BookRepository books = md.repository(BookRepository.class);
List<Book> recent = books.findByPublishedOnAfter(LocalDate.now().minusYears(1));
md.close();   // not mandatory — no internal pool, just a ServiceLoader cache to drop
```

- `md.repository(itf)` does `Class.forName(itf.getName() + "Impl")` (loaded once, cached in `MansartData`).
- The generated `Impl` has a public constructor `(RepositoryRuntime)` — `MansartData` injects the shared runtime.
- No reflection on `itf` itself: everything was resolved at `compile`.

### Mode B — CDI Vauban (BCE)

`mansart-data-processor` generates, in addition to `*RepositoryImpl`, a file `META-INF/mansart-repositories.list` (one line per detected `@Repository` interface — format: `fqn.OfInterface=fqn.OfImpl`).

At CDI startup, a `BuildCompatibleExtension` (BCE 4.1, provided by `mansart-data-cdi`):
1. Reads all `META-INF/mansart-repositories.list` resources via ClassLoader.
2. For each entry, declares a synthetic `@ApplicationScoped` bean typed on the interface, whose `create` method instantiates `Impl` with the `RepositoryRuntime` (itself a bean produced from an injected `DataSource`).
3. `DataSource` detection: by default `@Inject DataSource`, overridable via `@MansartDataSource("name")` on repository side.

→ **Added sub-module**: `mansart-data-cdi` (depends on `mansart-data-core` + `jakarta.cdi-api`). Only requires Vauban for tests — the BCE is standard CDI 4.1, so also compatible with Weld/OpenWebBeans for TCK.

```
mansart-jakarta-data/
├── …
├── mansart-data-cdi/          ← ADDED — CDI bootstrap (BCE + producers)
└── mansart-data-tck/
```

## Metamodel (decision 2 — detailed)

`mansart-data-processor` **systematically** generates `_Book`. It **also** generates `Book_` (standard JPA) **if** `jakarta.persistence-api` is on the user module's compile-classpath (detection: `processingEnv.getElementUtils().getTypeElement("jakarta.persistence.metamodel.SingularAttribute") != null`).

### `_Book` Format (Mansart, rich)

```java
@Generated("io.vidocq.mansart.data.processor")
public final class _Book {
    public static final EntityModel<Book> $MODEL = EntityModel.of(
        Book.class, "books",                                  // table
        List.of(/* attributes */),
        /* idAttribute */ /* versionAttribute */);

    public static final IdAttribute<Book, Long>             id          = …;
    public static final TextAttribute<Book>                  title       = …;
    public static final ReferenceAttribute<Book, Author>     author      = …;
    public static final TemporalAttribute<Book, LocalDate>   publishedOn = …;
    public static final VersionAttribute<Book, Integer>      version     = …;

    private _Book() {}
}
```

`Attribute` subtypes (`IdAttribute`, `TextAttribute`, `NumericAttribute`, `TemporalAttribute`, `ReferenceAttribute`, `EnumAttribute`, `VersionAttribute`) → allow the dialect SPI to generate specialized SQL without a chain of `instanceof`.

Each attribute exposes: `columnName()`, `javaType()`, `nullable()`, `unique()`, `MethodHandle getter()`, `MethodHandle setter()`. MethodHandles obtained via `MethodHandles.privateLookupIn(Book.class, lookup)` at `<clinit>` — **a single lookup**, never reflection at use.

### `Book_` Format (standard JPA, interop)

```java
@StaticMetamodel(Book.class)
public abstract class Book_ {
    public static volatile SingularAttribute<Book, Long>      id;
    public static volatile SingularAttribute<Book, String>    title;
    public static volatile SingularAttribute<Book, Author>    author;
    public static volatile SingularAttribute<Book, LocalDate> publishedOn;
    public static volatile SingularAttribute<Book, Integer>   version;
    public static final String ID = "id";
    public static final String TITLE = "title";
    // …
}
```

Initialized to null (JPA spec expects the JPA provider to set these fields at startup). When `mansart-persistence` arrives (M7), it will be responsible for populating. Meanwhile, `Book_` remains usable for **string column names** (the `ID`, `TITLE`, … constants) — useful for `@Query`.

## Mansart vs JPA Annotations (decision 3 — detailed)

`mansart-data-api` defines a **minimal set** of zero-dep annotations, mirrors of corresponding JPA annotations (same simple names, package `io.vidocq.mansart.data`):

| Mansart (zero-dep) | Recognized JPA Equivalent |
| --- | --- |
| `@io.vidocq.mansart.data.Entity` | `@jakarta.persistence.Entity` |
| `@Id` | `@Id` |
| `@GeneratedValue(strategy)` | same |
| `@Column(name, nullable, unique, length)` | same |
| `@Table(name, schema)` | same |
| `@Version` | same |
| `@Enumerated(STRING|ORDINAL)` | same |
| `@Embedded` / `@Embeddable` | same |
| `@ManyToOne(fetch)` / `@OneToOne(fetch)` | same (owning relations only in v1) |
| `@JoinColumn(name)` | same |
| `@Transient` | same |

**APT Rule**:
1. If `@jakarta.persistence.Entity` is present on the class → read JPA annotations.
2. Otherwise, if `@io.vidocq.mansart.data.Entity` is present → read Mansart annotations.
3. If both are present → clear compile error ("choose a single annotation set").

**Out of scope v1**: `@OneToMany`/`@ManyToMany` (collections), `@MappedSuperclass`, inheritance (`@Inheritance`), `@Convert`/`AttributeConverter`. Deferred to v1.1 or delegated to `mansart-persistence` (M7).

## SQL Naming Conventions (to validate)

By default, without `@Column`/`@Table`:
- Table name = plural snake_case of class name (`Book` → `books`, `OrderLine` → `order_lines`). Simple pluralization: add `s`, or `es` after `s/x/z/ch/sh`. Documented, overridable.
- Column name = snake_case of attribute name (`publishedOn` → `published_on`).
- Foreign key = `<attr>_id` (`author` (`@ManyToOne Author`) → column `author_id`).

**Open question #5**: automatic pluralization is nice but can surprise — alternative: class name in snake_case **without** pluralization (`book`, `order_line`). To decide before M2.

## SQLState Error Mapping → Jakarta Data Exceptions

| SQLState | Family | Jakarta Data Exception |
| --- | --- | --- |
| `23505` | unique violation | `EntityExists` |
| `23503` | FK violation | `MappingException` (to refine) |
| `23502` | NOT NULL violation | `MappingException` |
| `40001` | serialization failure (PG) | `OptimisticLockingFailureException` |
| `0` rows affected on `UPDATE … WHERE version = ?` | optimistic lock | `OptimisticLockingFailureException` |
| other | — | `DataException` (generic wrapper with `getCause()`) |

Implemented in a shared layer `mansart-data-core/SqlStateMapper`; the dialect can override via `Dialect.translate(SQLException)`.

## Compile-time Validation (by APT)

Clear errors emitted by `mansart-data-processor` when:
- `@Find List<Book> findByXyz(...)` but `xyz` is not an attribute of `Book` → `error: Book has no attribute 'xyz'`.
- Incompatible return type (`@Find Book findAllByXxx(...)` returns one but name suggests multiple).
- `@Query` JDQL syntactically invalid (M5).
- Repository references an entity without `@Entity`.
- Attribute without `@Id` on an entity.
- Multiple `@Id` without `@IdClass` (composite key deferred to v1.1).

**Goal**: zero runtime exception class due to misuse typable at compile-time.
